# 第十一周作业
结课作业
《基于智能体协作的狼人杀游戏系统开发》

# 题目背景
传统桌游类 AI 实现往往依赖规则引擎或有限状态机，缺乏角色个性、语言推理与社交博弈能力。随着大模型 Agent 技术的发展，我们有机会构建真正具备“角色扮演+策略推理+自然对话”能力的智能玩家。
本题要求使用主流 Agent 框架实现一个可运行、可观测的狼人杀游戏系统，探索 AI 在复杂社交决策场景中的表现。

# 技术要求（任选其一框架）
- 使用 LangChain + LangGraph / AutoGen / CrewAI 中任意一种框架
- 支持至少 5 名 AI 玩家参与（3村民 + 2狼人）
- 实现标准流程：夜晚行动 → 天亮公布死亡 → 发言环节 → 投票处决 → 夜晚行动 → 天亮公布死亡...村民/狼人获胜
- 每个 Agent 应具备：
    - 角色身份记忆（长期记忆管理）
    - 发言策略生成能力（基于当前局势推理）
    - 身份伪装或揭露行为（狼人需隐藏身份，村民可推理）

# 核心功能点（评分维度）
| 功能模块 | 具体要求 | 能力价值 |
|----------|----------|----------|
| 1. Agent 角色建模 | 定义不同角色 Prompt 模板（狼人/村民），并注入角色性格（如激进型狼人、谨慎型村民） | 强化提示工程与角色设定能力 |
| 2. 游戏流程控制 | 设计主持人（Moderator Agent）协调阶段流转，确保顺序正确 | 掌握多 Agent 协同调度机制 |
| 3. 记忆管理 | 实现跨轮次的记忆存储（例如谁说了什么、谁被怀疑过）；“情景记忆+语义记忆”机制；建议使用向量数据库（如 Milvus/Faiss 等）做语义记忆召回；在发言阶段，Agent 可检索历史发言记录进行反驳或佐证 | 在智能体评估中的重要性 |
| 4. RAG 增强推理 | RAG 在智能体评估中的重要性；体现 RAG 在 Agent 决策链中的作用 | 企业级系统成本量化评估的关注 |
| 5. 可视化执行追踪（加分项） | 输出每轮各 Agent 的思考链（Thought）、动作（Action）、观察（Observation）；“中间过程可视化”和“问题溯源” | 无明确对应能力价值 |
| 6. 成本与复杂度分析报告（附加任务） | 统计总调用 token 数、平均响应延迟、GPU 资源预估 | 企业级系统成本量化评估的关注 |

- Python 3.11+
- uv 包管理器
- 阿里云 DashScope API Key（通义千问）

### 方法 1：使用启动脚本（推荐）

```bash
./run_game.sh
```

### 方法 2：手动启动

```bash
# 1. 安装依赖
uv sync

# 2. 配置千问 API Key
cp .env.example .env
# 编辑 .env 文件，设置 DASHSCOPE_API_KEY=your-key-here

# 3. 运行游戏
uv run python -m werewolf.main

# 4. 查看日志（运行后）
ls logs/
# - werewolf_game_*.txt  # 可读文本日志
# - werewolf_game_*.json # 详细 JSON 日志
# - replay_*.json        # 游戏回放数据
```

## 🎮 游戏特色

### 🎭 角色系统
- **6名玩家**: 2个狼人 + 4个村民（超出最低要求）
- **中性名字**: Alpha, Beta, Alice, Bob, Charlie, David（不泄露身份）
- **5种性格**: 激进、谨慎、分析、情绪化、中立（基于 Prompt 工程）

### 🧠 智能记忆系统
- **双层记忆**: 情景记忆（短期）+ 语义记忆（长期）
- **向量数据库**: ChromaDB 存储和检索
- **RAG 增强**: 基于历史记忆的智能决策
- **记忆管理**: 每个 Agent 独立的记忆空间

### � 工具系统（5个工具）
1. **记忆检索** - 根据查询检索相关历史记忆
2. **玩家分析** - 分析特定玩家的历史行为和发言
3. **投票分析** - 分析候选人的可疑程度
4. **游戏状态查询** - 查询存活玩家、回合数等信息
5. **嫌疑跟踪** - 记录和查询对其他玩家的怀疑程度

**特色功能**: 所有工具输出自动过滤"狼人"/"村民"等身份标识，保护身份信息

### 🎯 游戏流程
1. **游戏开始** - 分配角色、初始化记忆
2. **狼人确认** - 狼人互相认识队友（标准流程）
3. **夜晚阶段** - 狼人协商选择目标
4. **讨论阶段** - 所有玩家分析和发言
5. **投票阶段** - 投票淘汰可疑玩家
6. **胜负判定** - 检查游戏结束条件
7. **循环** - 重复 3-6 步直到游戏结束

### 📊 可观测性
- **实时日志**: 控制台输出游戏进度
- **文本日志**: 可读的游戏记录（*.txt）
- **JSON日志**: 结构化的详细数据（*.json）
- **回放数据**: 支持后续分析和回放
- **CrewAI追踪**: 在线查看 Agent 执行过程

### 🔒 安全与合规
- **内容安全**: 移除所有暴力词汇（"杀死"→"出局"）

## 📊 成本分析

### 使用模型
- **LLM**: 阿里云通义千问 qwen-plus
- **价格**: ¥0.004/1K tokens（输入）、¥0.012/1K tokens（输出）
- **向量库**: ChromaDB（本地免费）

### 单局游戏成本
- **游戏时长**: 3-10 分钟（取决于回合数）
- **Token 使用**: 约 40,000-60,000 tokens/局（5-8轮）
- **预计成本**: ¥0.10-0.15/局
- **比较**: OpenAI GPT-4 约 ¥2-3/局（便宜 20 倍）

### 性能指标
- **平均响应时间**: 2-5 秒/次 Agent 调用
- **并发能力**: 支持多狼人同时决策
- **内存使用**: < 500MB（包括 ChromaDB）
- **存储需求**: ~1-2MB/局（日志+记忆）

详细分析见 [DESIGN.md Section 6](./DESIGN.md#6-成本与性能分析) 和 [QWEN_CONFIG.md](./QWEN_CONFIG.md)
